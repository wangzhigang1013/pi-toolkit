# Skill-prose 格式 — 写法规范

适用于**单任务 / 少数几个判别任务**（违规检测、战败判定、是非检测等）。范式来自「DCC 质检算法 Principle」里的各个 Skill 块。

空白模板见 `assets/template-prose.md`，本文件讲每段**怎么写**。

这种格式的产出基本可以**直接当算法的 prompt / skill 用**，所以措辞要像在给一个执行者下达可操作指令。

---

## 整体结构

```
# <任务名> Skill

## 任务说明        ← 一句话：分析什么内容，判断什么
## 业务背景        ← 可选：正常流程 vs 违规/异常场景，帮助理解为什么这么判
## 判断原则（Principles）
   ### Principle 1: <名称>
   ### Principle 2: <名称>
   ...
## 判断逻辑        ← 多 Principle 如何组合、命中顺序、输出取值
```

## 各段怎么写

### 任务说明
一句话讲清：分析**什么数据**（如"电销通话内容"），判断**什么结论**（如"是否属于线索归属违规"）。不超过两句。

### 业务背景（可选但强烈建议）
当判断依赖业务上下文时必写。结构通常是：
- **正常流程**：正常情况长什么样。
- **违规 / 异常场景**：要抓的目标行为长什么样、为什么发生。

背景让执行者理解判断意图，而不是机械匹配关键词。

### 判断原则（Principles）—— 核心
- 把判断拆成若干条**并列或有序的 Principle**，每条一个 `### Principle N: 名称`。
- 每条 Principle 内部固定写：
  1. **判断标准**：命中的核心特征。
  2. **核心关键词 / 表述**：用「」引号列具体话术，给真实口语。
  3. **排除**：明确什么**不算**，配反例话术。**排除项是 prose 格式里对应"负例边界"的部分，绝不能省。**
- 正例和排除都要给**贴近真实语料的话术示例**，用「」括起来。例：
  - 命中：`「不需要」「别联系了」「没兴趣」`
  - 排除：`「暂时不需要，再看看吧」「后续再看」`（→ 属于无明确意向，不算明确拒绝）
- 微妙边界要单独点出。如"单说没钱算明确拒绝，但'想买但没钱'不算"。

### 判断逻辑
讲清楚多条 Principle 怎么组合成最终结论：
- **命中顺序**：是否按顺序检查、命中即停。
- **组合规则**：命中任一即为 X / 须同时满足才为 Y。
- **输出取值**：明确字段名和取值。如 `命中任一 Principle → 正常战败（is_abnormal_defeat = 0）；都不命中 → 异常战败（is_abnormal_defeat = 1）`。

## 输出 schema
prose 格式的输出 schema 通常嵌在「判断逻辑」里，或单列一段。务必写明：
- 字段名（英文变量名 + 中文说明）
- 取值（0/1、枚举、是/否）
- 多任务时每个模块各自的输出

## 多任务文档
一份文档里有多个判别任务（如 F1 异常工单、F2 异常战败、F3 无意向），用表格组织成需求台账：
```
| Id | 任务 | 业务需求描述 | Principle | 补充(范围/输出/依赖) |
```
每个 Principle 单元格内部仍按上面的 Skill 块结构写。这种"台账 + 内嵌 Skill 块"的混合式适合给一期多个检测点定版。

## 常见错误
- 只写命中标准，漏掉**排除**项 → 等于没有负例边界。
- 关键词用书面语 → 和真实口语 ASR 文本对不上。
- 不写命中顺序 / 组合规则 → 多 Principle 同时命中时无所适从。
- 输出字段取值不明确 → 算法输出和评测口径对不上。
- 依赖业务知识却不写进背景（如"理想是直营模式，找售后的默认是车主"）→ 执行者无从判断。
